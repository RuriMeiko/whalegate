**Verify now proves an account can actually chat.** The old check only asked DeepSeek "is this token valid?", which a throttled account passes with flying colours — so a dead account looked healthy, and pressing Verify on a throttled one erased its warning label.

## Upgrade

From the dashboard (a banner appears once this release is live), or re-run the installer:

```sh
curl -fsSL https://raw.githubusercontent.com/RuriMeiko/whalegate/main/install.sh | sh
```
```powershell
irm https://raw.githubusercontent.com/RuriMeiko/whalegate/main/install.ps1 | iex
```

## Fixed

- **Verify checks real chat, not just auth.** `POST /api/accounts/{id}/verify` used to call `/users/current` and treat `code: 0` as healthy. It now runs a probe: auth first (to tell a revoked token apart from throttling), then one minimal real completion (`"hi"`, thinking and search off) on a throwaway session that is deleted afterwards. The result is one of `alive` / `throttled` / `auth_dead` / `unknown`.
- **Verify no longer erases a throttle label.** Previously any passing auth check wrote `ok` over `throttled`. Now only a successful chat clears it; a throttled probe keeps the label and pushes the account's cooldown out so the scheduler avoids it, and an inconclusive probe leaves the existing label untouched.
- **Reset has the same bar.** The Reset button clears errors and sessions as before, but its health check is also a real chat probe, so it cannot mark a throttled account as fine.
- **Bulk verify/reset reports why.** The toast now names the accounts that failed with their probe result (`auth_dead`, `throttled`) instead of only counting them.
- **Dashboard messages are specific:** "chat được, đã hết cooldown", "token còn sống nhưng chat trả rỗng — đang bị throttle", or "token bị từ chối — cần đăng nhập lại".

## Notes

- A probe spends one short completion per account. That is the only way to distinguish a working account from a throttled one; there is no cheaper endpoint that answers it.
- `sse_has_response` is shared with the streaming path and covered by tests for empty streams, init fragments, think-only output, and garbage lines.
- Unchanged: account storage, the API, and the update mechanism from 0.5.0.
