# v0.5.31

**DeepSeek rate limits are recognised and handled gently.**

- The stream parser now reads `hint` / `toast` events. A reply blocked with *"Tin nhắn quá thường xuyên"* (`finish_reason: rate_limit_reached`, closed with `click_behavior: "retry"`) used to look like an empty stream and was counted as a broken account; it is now logged as `[ds-hint]` / `[ds-ratelimit]` and handled as a rate limit.
- On a rate limit the account rests 30 s, 60 s, 120 s … (max 300 s) without touching its failure streak or "needs login" state, and whalegate **keeps the web session and waits instead of resending the whole conversation** to a new one. The same applies to `upload_file` answering `biz_code 7 "rate limit reached"`.
- The account learns a per-minute request ceiling from the block (requests sent in the last 60 s minus the blocked one, never below 3, forgotten after 30 min) and spaces later requests under it. New setting **Requests/minute per account** (`DS_MAX_RPM`, 0 = learn automatically) pins it by hand.
- If the rate limit outlasts the retries, clients get `429` (`rate_limit_exceeded`, `retry_after_secs`) instead of a generic `502`.
- Debug export: the header now lists the hidden/advanced settings, and each account line shows its rate-limit streak, ceiling and calls in the last minute; `stream_end` events record the hints and `retry_on_close`.
