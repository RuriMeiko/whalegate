# v0.5.27

Resume instead of fail over, the stream parser follows the real protocol, debug logs on disk, and a few dashboard fixes.

**Resume like the web does**
- When a stream breaks after some text arrived (no `close` event), the gateway first resumes it **on the same account**: `POST /chat/resume_stream` for up to 5 s (3 s wait per try, 1 s pause), then the *Continue* button's `POST /chat/continue` with `fallback_to_resume` after a short random pause. Only the part the client has not seen yet is forwarded. Only if both fail does the request fail over to another account.
- Checked against the live server: for a finished message both endpoints answer `biz_code: 22` with the whole message (or an SSE snapshot + `close`); for a running one they send a cumulative snapshot, then deltas, then `close`.
- After `CHALLENGE_REQUIRED` the gateway waits 2–5 s at random before trying another account instead of replaying the same payload at once.

**Stream parser**
- The parser now follows the web's patch protocol: inherited `p`/`o`, nested `BATCH` with relative paths, per-fragment types. Text carried inside `BATCH` events (citations such as `[reference:0]`, the last tokens together with the token usage, a new RESPONSE fragment opened inside a batch) used to be dropped.
- Replaying a real captured stream reproduces the server's final message exactly, also when cut at several points and resumed.

**`shumei_device_id`**
- Completion and continue bodies now carry `shumei_device_id` like the web: `"B"` + the decoded `.thumbcache_*` cookie of the account (`null` when absent). It changes on every page load; the server accepted a missing, null, old or garbage value in a live A/B test, so this is about matching the web, not a required field.

**Logs**
- Every log line is also saved to `logs/whalegate-YYYYMMDD.log` (7 days, 64 MB per file); detailed events (resume attempts, SSE tails of broken streams, account errors such as captcha) go to `logs/debug-YYYYMMDD.jsonl`.
- The log window has an **export** button: one debug bundle (version, settings, per-account summary, both logs for 24 h – 7 days). No tokens, cookies or labels.

**Dashboard**
- Adding an account: *Chrome riêng* first (log in **or sign up** in that window), then bookmarklet, extension, paste token (legacy).
- Money in `$` / `¥` / `₫` by language (rates in **Settings → Display**); Tokens / Saved / chart can show today / 7 days / 30 days / all time.
- Fixed clipped accents and the chevron in the range dropdowns; the dropdown list no longer has a filled background (Chrome 135+).
- README in English, Tiếng Việt and 简体中文.
