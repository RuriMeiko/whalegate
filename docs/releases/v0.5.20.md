**Add accounts from your own browser with one click, and accounts DeepSeek logs out leave the pool instead of failing over and over.** This release also closes a hole that exposed the dashboard through a tunnel.

## What changed

- **Bookmarklet.** In "+ Thêm", drag **Thêm vào whalegate** to the bookmarks bar once. Click it on a logged-in `chat.deepseek.com` tab and the account is added with that browser's own fingerprint: user agent, screen, GPU, timezone, languages and device id. Nothing goes through the URL, history or network. The data passes tab to tab, and the dashboard only accepts it from the DeepSeek tab that opened it.
- **Clicking again refreshes the account.** Adding a token that is already in the pool updates that account (cookies, device, browser profile) instead of reporting a duplicate. If you signed in again and got a new token, the same click swaps it into the existing account.
- **Logged-out accounts leave the pool.** DeepSeek has no way to renew a revoked token. When it logs an account out, whalegate stops picking it until it has a new token, instead of retrying it every 30 minutes. If every account is logged out, requests fail at once with `503 accounts_logged_out` instead of waiting in the queue.
  - The dashboard shows a red banner when several accounts are logged out together, which means DeepSeek revoked sessions on its side.
  - Chrome-login and pasted accounts get a **đăng nhập lại** button that reopens the account's own Chrome so you can sign in again.
- **DeepSeek errors are told apart.** Errors that came back as plain JSON were treated as throttling. whalegate now recognises: logged out, an hCaptcha challenge (the account rests 30 minutes and the log asks you to open DeepSeek with it), banned (removed from the pool), and IP limits or proof-of-work errors (the account is not blamed).
- **Security: tunnels no longer expose the dashboard.** Behind Cloudflare Tunnel, nginx or Caddy on the same machine, requests arrive from `127.0.0.1`, so the dashboard and the token export were reachable from the Internet. Requests carrying proxy headers now count as external: the dashboard and `/api/*` answer 403, and `/v1/*` requires `DS_API_KEY`.
- **Cloudflare Worker.** Failing over to the next instance works (the request body was lost after the first try). The client's token is no longer forwarded to instances, upstream addresses are no longer leaked, and `/v1/search/messages` is passed through. `worker/deploy.sh` deploys it with a Cloudflare API token and checks the result. See the README.

## Upgrade

From the dashboard, or re-run the installer:

    curl -fsSL https://raw.githubusercontent.com/RuriMeiko/whalegate/main/install.sh | sh

    irm https://raw.githubusercontent.com/RuriMeiko/whalegate/main/install.ps1 | iex

If you use the bookmarklet, drag it from the dashboard again after upgrading.
