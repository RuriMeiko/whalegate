# v0.5.33

**Cloudflare Worker egress, muted accounts, gentler failover.**

### Cloudflare Worker as the egress IP
- New **cloudflare** button on the dashboard: finds Node.js (or downloads it from nodejs.org and checks its SHA-256), runs `wrangler login` (you only press *Allow*), deploys the `ds-egress` Worker, sets its key, switches it on and measures the egress IP. It also lists the Worker with an ON/OFF switch, *check* and *remove*, and counts the connections sent through it against the daily quota of your plan (Free = 100,000).
- It is a TCP tunnel, not URL rewriting: whalegate runs a local CONNECT proxy that reaches the Worker over a WebSocket and the Worker opens the socket to DeepSeek. TLS stays end-to-end, so the TLS/HTTP2 fingerprint is still the emulated Chrome. Both whalegate's HTTP client **and every account Chrome window** (sign in, sign up, *open Chrome*, device refresh) use it; WebRTC UDP leaks are blocked in those windows.
- Targets that sit on Cloudflare's own IP ranges (hCaptcha, many CDNs) cannot be reached from a Worker, so they are connected directly from your machine. The dialog shows how many went direct. Note that hCaptcha therefore sees your IP while DeepSeek sees Cloudflare's.
- Mind Cloudflare's terms: using a Worker as a general TCP proxy may breach them. The key is required, mail ports are blocked, and only DeepSeek-bound traffic is meant to use it. Egress IPs rotate inside Cloudflare's range, so one account may change IP between requests.
- Files: `worker/egress.js`, `worker/deploy-egress.sh`, tests in `worker/egress.test.mjs`.

### Accounts
- **Muted accounts** (`biz_code 5`, `mute_until`) rest until the mute ends, say so on the dashboard and in *verify*, and no longer count as failures.
- **Open Chrome** button on every account that has its own Chrome: the same profile, session and fingerprint, so you can solve a captcha yourself; closing the window saves the session and lifts a hCaptcha rest. Logged-out accounts only show *log in again*, which closes the window by itself when you are in.
- The sign-in form is pre-filled with the email and password you typed the last time (kept in `~/.whalegate/credentials.json`, mode 0600, never in backups, removed with the account); whalegate never presses *Sign in* for you.
- The dashboard no longer swallows clicks: the account list is not redrawn while the pointer is down.

### Fewer rate limits and captchas
- A continuation now **waits for the account that holds the session** (up to ~35 s, e.g. the 6-calls-per-30-s burst window) instead of resending the whole context to another account, and after a rate limit it stays on the same account when the context is large. Challenges log their `provider`.
- New settings: *Requests/minute per account* (`DS_MAX_RPM`), *Web-like background traffic* (`DS_WEB_BOOT`, now switchable live), Cloudflare Worker URL / key / on-off / daily quota.
- Debug export lists the hidden settings and each account's rate-limit state; the Worker key is redacted.
