**Self-update now works on Windows.** The updater downloaded and verified the new build, then stopped with "Windows không thay được file đang chạy" and left the old binary in place, so every Windows user was stuck on whatever version they installed first.

## Upgrade

From the dashboard, or re-run the installer:

    curl -fsSL https://raw.githubusercontent.com/RuriMeiko/whalegate/main/install.sh | sh

    irm https://raw.githubusercontent.com/RuriMeiko/whalegate/main/install.ps1 | iex

Windows users on 0.5.3 or older need this one update by hand: download the 0.5.4 archive from the releases page, quit whalegate, replace the exe, and start it again. From 0.5.4 onward the in-app button works.

## Fixed

- **Windows update no longer dead-ends.** Windows locks a running .exe, so renaming over it always fails with access denied. The updater now copies the new binary next to the old one and writes a small .bat helper that waits for the process to exit, replaces the file with move /y, and relaunches the app; the helper deletes itself afterwards.
- **Restart hands over to the helper.** On Windows the restart path launches that script instead of trying to exec the old binary, which was still locked anyway.
- **No stale helper loop.** The script only runs when both the .bat and the staged .exe.new are still present; a leftover script from an abandoned update is deleted instead of being replayed on the next restart.

## Notes

- Linux and macOS are unchanged: they replace the binary in place and re-exec, which already worked.
- The .bat helper quotes both paths, so an install directory with spaces (Program Files) is fine, and it retries until the old process releases its handle.
- One new test checks the generated script: quoted paths, move /y over the old binary, the retry loop, the relaunch, self-deletion and CRLF line endings.
