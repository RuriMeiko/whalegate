# v0.5.37

- **Several Cloudflare Workers.** The Cloudflare button can now add a Worker on a second (third…) Cloudflare account (*+ Thêm Worker bằng account Cloudflare khác*, up to 8). Each DeepSeek account is pinned to one Worker by its fingerprint seed, so its IP does not jump between runs, and its Chrome window uses the same Worker as its requests. The popup shows IP, colo and quota per Worker. The old single `DS_EGRESS_URL` / `DS_EGRESS_KEY` setting is migrated automatically into the new `DS_EGRESS_WORKERS` list (usage history is kept).
- **Settings reorganised.** The dialog is wider and split into tabs. The *IP đầu ra* tab explains the three routes an account can take, in order: ① own proxy → ② Cloudflare Worker → ③ direct from your home IP, with a small diagram that shows which ones are active. Long descriptions are folded behind a **?** button. Scrollbars now match the theme.
- **Smaller default context window: 256K tokens (was 512K).** `DS_CONTEXT_TOKENS` is now `256000` and `DS_PROMPT_MAX_CHARS` is `912000` (was `1822000`), so the window dsh is told about and the point where the gateway trims history stay consistent. Reason: the web app accepts ≥512K, but very large prompts are the most conspicuous thing an account sends, and we have seen accounts get muted or suspended; staying at half the size is a precaution to lower the chance of being scanned and flagged. This is a precaution, not a proven cause. If you set these values yourself in Settings, your values are kept; re-run the dsh setup to sync its window.
- Fix: setting up a Worker on a Cloudflare account without a `workers.dev` address failed with *register a workers.dev subdomain*. The address is now registered automatically.
- Fix: clicking the dimmed area outside a popup no longer closes it.
- Fix: in Settings, an edited row now turns *unsaved*, and the ↺ button works.
- Known limit: an account's Chrome window uses ② or ③ only; it does not go through the own proxy ①.
