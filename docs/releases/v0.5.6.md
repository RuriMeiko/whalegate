**Tool calls with broken closing tags run instead of leaking as text.** In a dsh session the model wrote two tool-call blocks and closed both wrongly. The first block showed up in the chat as raw `<｜｜DSML｜｜ …>` markup. The second ran with its code cut off at a heredoc and failed with "Unterminated template".

## Upgrade

From the dashboard, or re-run the installer:

    curl -fsSL https://raw.githubusercontent.com/RuriMeiko/whalegate/main/install.sh | sh

    irm https://raw.githubusercontent.com/RuriMeiko/whalegate/main/install.ps1 | iex

## Fixed

- **Blocks closed with `</｜｜DSML｜｜>` and a reopened `calls` are parsed.** The model closed its last parameter with a bare `</｜｜DSML｜｜>`, then wrote `<｜｜DSML｜｜ calls>` (no slash) where `</invoke></calls>` belonged, sometimes twice in a row. The DSML parser saw an invoke that never closed, treated it as a truncated stream and dropped the block. A fallback parser then picked up the second block and ended the value at its first `<`, which was the `<<'PY'` of a heredoc. Now, when `calls` reopens or a new `invoke` starts while an invoke is open and no parameter is pending, that invoke is closed there. Both calls run, with the heredoc intact.
- **No stray `<｜` at the start of a reply.** Replies sometimes began with `<｜` glued to the first word (`<｜我是…`). The fragment is now dropped and the text is kept. Real markers such as `<｜工具调用｜>`, `<｜调用工具>` and `<｜end▁of▁sentence｜>` are left alone, because they contain `｜` or `>` within the first few characters.

## Notes

- If the model switches language, for example answering in Chinese after a role-play request, that is the model's choice and whalegate does not rewrite it. Only the leftover `<｜` is removed.
- New tests cover the real two-block sample and the `<｜` rules. The streaming corpus also gained both samples, so they are checked with random chunk splits too. Replaying the 61 saved failure samples gives the same result as 0.5.5 (49 parse, 12 junk retried), so there is no regression.
